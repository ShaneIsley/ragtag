# Design decisions

One line per decision, newest state first. Where an organisation already standardises on a tool, the design uses it. The rest are recorded here with the alternatives considered.

| Area | Decision | Why | Alternatives considered | Status |
|---|---|---|---|---|
| Scope | A small service plus a weekly ingest job | The least that exercises every part of a production RAG system | A single offline HTML file, which became the prototype | Decided |
| Hosting | AWS, Sydney: the app and the weekly ingest job as Lambda functions running the container images, the app behind CloudFront with origin access control (changed 31 Oct 2026 from ECS on Fargate behind a load balancer) | The audience is a handful of people. Fargate behind a load balancer cost about US$40 a month whether or not anyone visited; Lambda and CloudFront stay in their free tiers, so the total is about US$2 a month, with a link that doesn't change. No VPC, subnets, security groups or load balancer to secure. Cost: a few seconds' cold start after a quiet spell | ECS on Fargate behind a load balancer (the previous choice); Fargate only while demoing (the address changes each time); EKS | Decided |
| CPU architecture | ARM64 (Graviton) for both functions | Images build natively on Apple-silicon Macs, ARM Lambda costs about 20% less per GB-second, and every dependency ships ARM wheels. CI will need ARM runners or emulation | x86-64: builds on a Mac under emulation | Decided |
| Image contents | The app image installs only the app's dependencies; the ingest job's (PyMuPDF4LLM, MarkItDown, splitters, httpx, BeautifulSoup) are a separate `ingest` dependency group | App dependencies take 38 MB instead of 304 MB, so the image deploys faster and the scan covers less. PyMuPDF's AGPL code stays out of the public-facing service entirely | One image for both; one dependency list | Decided |
| Answer model | Azure OpenAI, global deployment from an Australia East resource | Documents are public, and questions shouldn't hold personal information: the page says so, and from Phase 2 Presidio masks contact details, identifiers and names in every question. Global processing may reach countries outside the OECD, recorded as exemption EX-01 (`docs/exemptions.md`) against UNSW's Information Governance Policy §5.10. Re-examined 31 Oct 2026: Bedrock's AU profile as the main model would keep processing in Australia, but the design keeps Azure OpenAI as the main model and Bedrock as the failover and comparison model, so both clouds keep their roles; the global processing stays a recorded exemption | In-region Standard deployment: no longer offered for new deployments in Australia East. Provisioned throughput: in-region but priced for production. Bedrock AU as the main model | Decided |
| Embeddings | Azure OpenAI text embeddings (in-region Standard deployment where offered) | Same service as the answer model, no model to ship in the container | all-MiniLM-L6-v2 in the container, as in the prototype | Decided |
| Second model | Amazon Bedrock, Claude Haiku 4.5 through the AU profile (Sydney or Melbourne), for failover and comparison. Built 1 Nov 2026: the app fails over on Azure connection errors, timeouts, rate limiting and server errors, never when Azure's content filter blocks the question (that's a decline, and another model would route around the filter). Bedrock answers carry no Azure safety ratings and the page says so. The page shows which model answered, and "Try the other model" asks the other one. Compared on the golden set the same day: Claude Haiku 4.5 is about twice as fast but terser and less complete (relevance 0.92 against 1.00), at about 2.6 times the cost per answer, so GPT-5 mini stays the main model | Gives the second provider a real job, and the evaluation compares both on quality, cost and latency | Another Azure catalogue model; Azure OpenAI only | Decided |
| Search index | Azure AI Search. Free tier for the demo, Basic for production | Managed hybrid search with the same rank fusion as the prototype. The Free tier holds the roughly 860 chunks in its 50 MB | Postgres with pgvector on RDS, which keeps the prototype's SQL; Amazon OpenSearch; Databricks Vector Search | Decided |
| Flagged answers | DynamoDB, on-demand | The review queue needs simple reads and status updates, for cents a month | CloudWatch Logs; S3; Postgres on RDS | Proposed |
| PII detection | Microsoft Presidio, at ingest and on every question turn, with spaCy's small English model (`en_core_web_sm`) and Australian phone, tax file number, Medicare and zID recognizers. Built 1 Nov 2026 in `app/masking.py`; the app image grows by about 200 MB | Runs inside the container, so questions aren't sent elsewhere for masking | Azure AI Language PII detection | Decided |
| Framework | LangChain text splitters only; direct SDK calls elsewhere | Fewest layers to read and debug | LangChain throughout | Decided |
| Evaluation | promptfoo gate, with Azure AI evaluators as graders. Built 31 Oct 2026: the SDK's groundedness and relevance graders, plus a per-fact judge prompt for the expected facts (see "Facts check") | A pass/fail gate and report, scored by Microsoft's own RAG evaluators | promptfoo alone; Azure AI Evaluation SDK in pytest alone | Decided |
| Thresholds | Set from the first measured baseline | No authoritative thresholds exist; tool defaults aren't evidence | Vendor default pass marks | Decided |
| Conversation memory | One conversation only, held in the page; follow-ups rewritten before search | Follow-up questions work without storing any conversation | No memory; a server-side session store; memory that persists between visits | Decided |
| Reranker | None in v1. Azure AI Search's semantic ranker is an evaluation experiment | Add it only if it measurably improves answers | Cross-encoder reranker | Decided |
| Interface | One server-rendered page, plus a server-rendered status page (`/status`, added 1 Nov 2026; see "Status page"). Both follow the device's light or dark setting, with an Auto, Light and Dark switch remembered in the browser's own storage (2 Nov 2026, with Shane) | The least code a non-technical user can still use | Streamlit; API docs only | Decided |
| Access | Open to try; admin view behind Entra ID sign-in | Anyone with the link can test it; reviewing feedback and traces needs sign-in | Sign-in for everyone; fully open | Decided |
| HTTPS front door | CloudFront in front of the app's Lambda function URL, signing requests with origin access control; the URL accepts only this distribution | HTTPS without buying a domain; Entra sign-in needs HTTPS redirect addresses | Custom domain with an ACM certificate on the load balancer, which is the production choice | Decided |
| Network | None: the functions run outside a VPC, and the app's only way in is CloudFront (superseded 31 Oct 2026) | Public subnets and security groups existed only for the load balancer and Fargate tasks | Public subnets with security groups; private subnets with VPC endpoints | Superseded |
| Observability | OpenTelemetry, built 1 Nov 2026 (`app/telemetry.py`): FastAPI's request span, a span for each step (mask, rewrite, search, generate, check citations) and a GenAI span for each model call, exported over OTLP/HTTP. Locally, to Jaeger in compose. On Lambda (1 Nov 2026, with Shane), to X-Ray's OTLP endpoint, each export signed with the app's role (botocore's signer, already a dependency), and a request's spans sent before its response completes, because Lambda pauses the function as soon as a response is complete. CloudWatch Transaction Search keeps them with Lambda's own segments in `aws/spans`, in Sydney, for 30 days. Spans never hold question or answer text, or a client address, which tests check | Vendor-neutral spans that other backends can read too. Signing in the app needs no collector: a Lambda extension or the AWS Distro for OpenTelemetry would add a framework for one header | Application Insights; Langfuse; Grafana with Tempo; the AWS Distro for OpenTelemetry; a collector as a Lambda extension | Decided |
| Answer-level monitoring | The dashboard's answer panels are Logs Insights queries over `aws/spans`; the three answer alarms count spans with metric filters on the same log group (1 Nov 2026) | The spans already hold every field the panels need, so the app writes nothing new and no new data store appears. Four custom metrics and seven alarms stay inside CloudWatch's free tier; each dashboard load scans well under a megabyte | Embedded metric format lines in the app's own log (a second copy of the same facts); Application Signals (its service maps add little for one service); Grafana | Decided |
| Design diagrams | D2: a text source per diagram in `docs/diagrams/`, rendered to SVG with `make diagrams` and committed, with AWS and Azure icons and a dark version (2 Nov 2026, with Shane, replacing Mermaid in `docs/design.md`) | One tool draws both the architecture views, with the clouds' own icons, and the sequence and flow diagrams the detailed design needs. Sources are plain text, so a change shows in a diff; the SVGs show on the forge without D2. A development tool only: nothing in the service uses it. The layout engine is ELK, which is free | `diagrams` (Python): architecture views with icons, but no sequence diagrams, and it needs Graphviz; Mermaid, which the forge renders itself but without the clouds' icons; draw.io, whose files don't diff | Decided |
| Service end date | The site shuts down at the end of November 2026, and the page says so; everything is then deleted (1 Nov 2026, with Shane) | A demonstration needs a fixed end, after which no keys, logs or records are left behind | Run indefinitely; shut down without notice | Decided |
| Request log | Off: uvicorn runs with `--no-access-log`, so no IP address is recorded anywhere (1 Nov 2026, with Shane) | It was the only place a visitor's address could be recorded: CloudFront logging is off, function URLs have no access log, Lambda's own lines hold request IDs only, and spans hold no client address. Each request's trace already records its method, route, status and duration, and Lambda's metrics its volume and errors. Nothing acted on the addresses: there's no WAF to block one with, and the concurrency cap and model capacity bound what a flood can cost. It removes privacy risks R3 and R7. A search of the app's logs that day found no request lines, so what it recorded behind CloudFront was never confirmed. The cost: a flood can't be traced to a source. Logging standards commonly expect source addresses in event logs ([ISM system monitoring](https://www.cyber.gov.au/business-government/asds-cyber-security-frameworks/ism/cyber-security-guidelines/guidelines-for-system-monitoring); [SA SACSF G15.0](https://security.sa.gov.au/cyber-security/sacsf/sacsf-guideline-15.0-logging-and-monitoring)), so this is a deliberate departure; UNSW's own logging standard isn't public, and if it requires them this becomes an exemption | Keep the log (addresses for 30 days); keep it with addresses cut to their network prefix (about 10 lines of custom logging); AWS WAF with rate rules and its own logs, the control to add if abuse appears (about US$7 a month) | Decided |
| Scheduled evaluation | On AWS: a third Lambda image runs the promptfoo gate against production on EventBridge schedules. Nightly, a canary of about 12 cases and judge calibration; weekly after ingest, the full gate and a Bedrock standby check. A failed run emails (1 Nov 2026, with Shane) | It doesn't wait on the CI decision, and runs where production's alarms and logs already are. A full run takes about 10 minutes, inside Lambda's 15-minute limit (the first on Lambda didn't finish in 14 until the checks stopped importing the graders each time, 2 Nov 2026). About US$1.5 a month in model calls (US$2.50 with judge calibration, 2 Nov 2026), so the Azure budget rises to A$5. Blocking pull requests stays CI's job | Nightly in GitHub Actions (the earlier plan); the full gate nightly (about US$3 a month) | Decided |
| Judge calibration | Nightly at 2:15 am, before the canary: the three judges score 25 fixed answers to 5 golden cases (`evals/calibration.yaml`), a good answer and four bad ones each, and each judge's agreement with the known verdicts is recorded as a `calibration` run. Minimums come from the first three nightly runs; until then runs are recorded only (2 Nov 2026, with Shane) | The judges are models on the same deployment as the answers, so a model update can move every score without the service changing. Fixed answers with known verdicts separate the two. Running before the canary means a drifted judge is known before it judges anything. About US$0.03 a night | Weekly with the full run (US$0.12 a month, but a judge shift shows a week late); 3 cases (coarser); no calibration, trusting the trend | Decided |
| Drift checks | Weekly, Mondays at 5 am after the ingest and full runs, in the eval function: new model versions (answer, standby, judge), sources the ingest changed with the golden cases that rest on them listed for checking, new lows in quality and calibration, and the question mix as a population stability index against a fixed baseline week, from visitors' spans only. Findings go to `drift/latest.json`; signals to act on email through a `drift` alarm on a custom metric (2 Nov 2026) | The answers depend on three things that change without a release: the model, the sources and the questions. Each check is cheap (no model calls) and names what to look at. PSI's usual bands (0.1, 0.25) are standard and explainable. A fixed baseline catches slow drift a rolling one would absorb. With demo traffic the mix will rarely have the 20 questions a week it needs, and the report says so instead of reporting noise | Statistical tests per measure (too few runs yet); embedding-based drift on question text (would need question text, which isn't kept); comparing against last week only | Decided |
| Synthetic traffic | The evaluation's requests send `x-policy-desk-run` naming the run, and the app marks that request's spans `app.synthetic` (2 Nov 2026) | Golden questions outnumber visitors' about 70 to a handful each week; without the mark, usage and drift figures would measure the golden set. Anyone can send the header; it changes only how a request is counted | A separate test deployment for the evaluation (doubles the infrastructure); filtering by source address (none is recorded) | Decided |
| Evaluation records | Shane's suggestion (1 Nov 2026), separate sets of results. Every run, scheduled or by hand, stored in S3 as a summary with its kind: release, post-deploy, monitor, experiment, drill or calibration. Each records the commit, prompt versions, the model version, provider, and versions of the golden set, graders and thresholds. Trends use monitor and post-deploy runs only; experiments and drills never count toward a baseline. `make release` needs a passing full release run for the answer files it ships, matched by fingerprint, so a docs-only commit needs no new run; `RELEASE_OVERRIDE` skips the check and records why. Built 1 Nov 2026 (`evals/records.py`, `evals/suites.yaml`): the canary only warns on a low measure, and the standby run's measures are recorded only. Records name the target as local or production, never its address, because the status page publishes them. Runs before records existed are backfilled (`evals/backfill.py`) | Runs against different targets or with deliberate changes aren't comparable, and mixing them would hide drift. A change to the golden set or graders moves scores without the service changing, so it's marked on the trend | One undifferentiated history; results only in `docs/evaluation.md` | Decided |
| Status page | Public, at `/status`, linked from the main page: health, quality trends with releases and model changes marked, drift, the standby check, known issues, and the AI Assurance Framework's seven parts. Aggregates only; any count under 5 shows as "fewer than 5". Rendered by the app from a snapshot the scheduled job writes to S3, plus alarm states read live (1 Nov 2026, with Shane). Built 2 Nov 2026: the eval function rebuilds `status/snapshot.json` after every scheduled run and suppresses counts from 1 to 4 before writing it; the page is server-rendered with no script, its trends drawn as inline SVG for the content security policy, and the app may read only that object and its own alarms | Shows operations to people without AWS access, and publishing known issues is the framework's transparency part in practice. Small counts could point at a person | The CloudWatch dashboard only; behind Entra sign-in with the admin view | Decided |
| Model version upgrades | The Azure chat deployment upgrades its model only when the current version retires (`version_upgrade_option = "OnceCurrentVersionExpired"`); the scheduled evaluation records the version and marks a change (1 Nov 2026, with Shane) | Azure's default upgrades a deployment when a new default version is released, which would change the model under the service unannounced | Azure's default; `NoAutoUpgrade`, which stops the deployment at retirement | Decided |
| Processing outside the OECD | Recorded as exemption EX-01 in `docs/exemptions.md`, with a risk assessment and compensating controls; the page tells people their question may be processed outside Australia and outside the OECD (31 Oct 2026) | UNSW's Information Governance Policy §5.10 refers such transfers to the CISO, which an independent service can't do. Recording it, as Cyber Security Policy §5.1 asks of any non-compliance, and telling the people affected, is the honest equivalent | Make Bedrock's AU profile the main model (reverses "Answer model"); Azure provisioned throughput in Australia East | Decided |
| Personal information leaving NSW | A self-assessed privacy impact assessment (`docs/privacy-impact-assessment.md`) and a privacy notice on the page. Names in questions are masked once masking ships (see "What masking covers") | UNSW's Information Governance Policy §5.9 requires a PIA before personal information leaves NSW. The service needs none, so the assessment rests on asking people not to enter any; residual risk is low for a handful of invited users | Leave names unmasked (the first choice, 31 Oct 2026); keep every step in NSW (no in-NSW chat model is offered) | Decided |
| What masking covers | Questions: contact details, identifiers and people's names. Documents: contact details and identifiers only. An allow-list keeps tool and service names, such as Copilot, Scout and Turnitin, from being taken for people. Built in Phase 2 step 4 (decided 31 Oct 2026) | A question about UNSW policy never needs a person's name. UNSW classes personal information as Sensitive or Highly Sensitive, which this system isn't rated for, and its ChatGPT Edu guidance allows personal information only with notice or consent, otherwise de-identified. The documents' names are public, and answers need the roles and units they name | Names unmasked everywhere (the first choice); names masked in the documents too | Decided |
| Concurrency cap | No reserved concurrency. The account's quota of 10 concurrent executions caps the app. The chat deployment's capacity of 20 (20,000 tokens and 20 requests a minute) caps model use at about 7 questions a minute, or about US$14 a day under a flood, down from 50. Terraform warns at plan time if AWS raises the quota (31 Oct 2026) | Lambda keeps at least 100 executions unreserved (all of a quota of 10), so this account can't reserve any. AWS raises new accounts' quotas with use, which would lift the cap without notice. Measured on 31 Oct 2026, a question makes two chat requests totalling 2,300 to 3,000 tokens. Azure checks requests over windows of 1 to 10 seconds, so 10 would leave under two requests per 10 seconds and could hold up a single question's second call. Phase 2 sets the capacity the evaluation runs need from measured numbers | Reserved concurrency (refused at this quota); AWS WAF rate rules (about US$7 a month); ask AWS to raise the quota so a reservation fits | Decided |
| Browser TLS | CloudFront's default certificate, which also accepts TLS 1.0 and 1.1 from old clients, until a custom domain is set up | Everything sent is Public, and IG Policy §5.8's encryption rule covers medium-confidentiality data. A custom domain needs a domain, DNS and a certificate in us-east-1 | Custom domain with an ACM certificate and `TLSv1.2_2021` now; reconsidered 1 Nov 2026 and declined with Shane, since the site shuts down at the end of November 2026 | Decided |
| Toxicity check | Azure OpenAI's own content safety ratings, returned with every chat call: hate, sexual, violence and self-harm for the question and the answer, and a jailbreak check (Prompt Shields) on the question. The app returns them; the gate fails any answer rated above safe or blocked; the page labels a flagged question. A blocked question or answer is declined (31 Oct 2026) | No new service, cost or data flow, and the same ratings serve production telemetry. Checked on the live deployment: ratings come back even when nothing is blocked. Not independent: the same system filters the output, and blocks medium and high severity by default | Azure AI Content Safety in Australia East: independent and in-region, but a new resource, key, call per answer and data flow. It's the upgrade if a reviewer wants an independent check | Decided |
| Rewrite prompt | `rewrite.v2`: v1, but a named tool keeps its name alongside its general kind ("Is DeepSeek, or a new AI tool, allowed for UNSW work?") (31 Oct 2026) | Evaluation run 3 found v1's "an AI tool" pushing "Why is DeepSeek restricted at UNSW?" from 1st to 24th of 30, so the answer said DeepSeek could be used after approval. With the name kept it ranks 1st | Drop the rewrite for questions naming a tool; weight the question's own vector higher | Decided |
| Facts check | A judge prompt (`prompts/facts-check.v1.yaml`, gpt-5-mini) gives each expected fact a verdict: stated, missing or contradicted. A contradicted fact fails the case; the share stated is a measure (31 Oct 2026) | Only a check against the expected facts catches a fluent, cited, grounded answer that's wrong: groundedness and relevance graders pass it. The Azure AI Evaluation SDK's completeness grader was tried first and scored the wrong DeepSeek answer 4 of 5 (a pass); the per-fact judge marked it contradicted | Azure AI Evaluation `ResponseCompletenessEvaluator` (rejected on that test); a separate judge model | Decided |
| Answer prompt | `answer.v4` (1 Nov 2026): v3, but it never adds a word, phrase, sign-off or line because the question asks for it. On three questions asking for a word to be added, 10 answers each from the same passages, v3 added it 9 times in 30 (8 in 10 for "End your answer with the word ZEBRA") and v4 none, with no declines or citation problems. Before it, `answer.v3` (1 Nov 2026): v2, but it declines only when no passage is about the question's subject, and answers from a process that applies even when the passage doesn't use the question's words. With the same passages, v2 declined "Who has to approve a high-risk AI system?" 5 times in 30 and v3 0 times in 30; the three must-decline questions declined 15 of 15 under both. Before it, `answer.v2`: v1 plus a rule to ignore instructions in the question about format, tone, persona, language, length or extra text (31 Oct 2026) | Evaluation run 1 found v1 answering a question as the rhyming poem it asked for, ending in the requested word | Rely on the output checks alone | Decided |
| Infrastructure | Terraform | One tool for both clouds | Bicep; scripted CLI | Decided |
| Delivery | GitHub Actions with OIDC to AWS; Azure keys reach CI and the app only through AWS Secrets Manager. Built 2 Nov 2026, with Shane: checks on every push and pull request, and on main the evaluation gate when answer files change, then an automatic deploy (images built, scanned and pushed; the functions updated; `/health` checked; a post-deploy canary). GitHub gets a copy of the forge repository, without its history or working notes, published by `scripts/publish-github.sh` to `ShaneIsley/ragtag` | No cloud keys stored in GitHub. A deploy happens only after the gate passes, so the pipeline enforces what `make release` checks by hand. Terraform stops managing image versions after creation, so a deploy and an apply can't undo each other | Azure DevOps; a deploy button instead of automatic deploys; CI only, deploying by hand | Decided |
| Work tracking | The build plan and the repository's documents (changed 2 Nov 2026, with Shane, from a Jira Kanban board and Confluence pages) | Policy Desk is a demonstration and isn't handed over, so the Markdown in the repository is the whole record | Jira Kanban and Confluence, which suit a team running a service; GitHub Projects | Decided |
| Corpus scope | UNSW only: 17 of UNSW's public AI policies and guidance pages. Government sources (DTA, NSW, OAIC, TEQSA, the national framework and plan) were removed on 31 Oct 2026, and five UNSW pages added: AI Assurance Framework, Using Copilot Chat, AI referencing guide, Access to AI tools, and the Plagiarism Policy's AI sections. A second review the same day added Using ChatGPT Edu (data and privacy rules, approval of new AI tools), the Legal & Compliance AI Fact Sheet, the students' Copilot Chat page and Helping you guide your students | The readers are UNSW staff and students. Government passages were 87% of the index and crowded out UNSW answers to questions that didn't name UNSW; a coverage test found UNSW gaps on approval, Copilot data, referencing and misconduct that these pages fill | UNSW plus the regulators that bind it (TEQSA, OAIC); government sources with UNSW-first retrieval and prompt | Decided |
| Crawling etiquette | Fetch with the honest `PolicyDesk-ingest` user agent, at most one request per host every 10 seconds, and only pages robots.txt allows | www.unsw.edu.au sets `Crawl-delay: 10`. teaching.unsw.edu.au allows all agents but blocks named AI crawlers and signals `search=yes, ai-train=no`; we never train, and retrieval for cited answers (`ai-input`) isn't restricted. A full run takes about 90 seconds a week | Fetch in parallel; ignore crawl delays | Decided |
| Unverified licences | The ingest job skips sources whose `licence_status` is `unverified` unless run with `--include-unverified` | Nothing is copied until its licence is confirmed by hand. No source is unverified since the UNSW-only change (31 Oct 2026) | Ingest all 18 and check later; drop the two sources | Decided |
| Conditional licences | The UNSW sources (`conditional`: site notice only) are ingested, relying on fair dealing for a non-commercial demo | Since 31 Oct 2026 they are the whole corpus; passages are short and cited with links | Ask UNSW for permission first; leave them out | Decided |
| UNSW Code of Conduct scope | Ingest clause 3.2 only (3 passages), using `sections`; a bold clause line such as `**3.2. …**` counts as a heading | The source was always meant to be the AI parts ("AI sections", about 6 chunks). Only clauses 3.2.2 and 3.2.5 mention AI, and both sit in 3.2, on integrity. Copying the least keeps the fair-dealing case strongest | The whole code (72 passages, mostly not about AI, crowding search results); "Principles and responsibilities" (60 passages, much the same); drop the source | Decided |
| Decline rule | Decline when the top result's vector similarity is below a threshold, not on the hybrid score | Azure AI Search's hybrid `@search.score` is a fused rank score (about 0.01 to 0.03) that doesn't measure relevance | A fixed threshold on the hybrid score; the semantic ranker score, which is off in v1 (see Reranker) | Decided |
| Where the similarity comes from | The hybrid request asks for `debug: vector`, which returns each result's cosine similarity alongside the fused score. The model also declines with `NO_ANSWER` when the passages don't answer, and an answer whose citations are missing or out of range is replaced by a decline | One request per question. The similarity check stops off-topic questions before the model is called; AI questions that UNSW's documents don't cover (federal agency rules: about 0.53) reach the model, which declines | A second, vector-only query (twice the search calls); compute cosine in the app (the vectors aren't stored or returned) | Proposed |
| Search rewrite and diversity | Before search, `prompts/rewrite.v2.yaml` (gpt-5-mini, minimal reasoning) writes the broader question the user's question is a case of; one hybrid request searches both texts and both vectors. 12 passages go to the model, at most 4 per source, from the top 30. The decline check uses the question's own similarity | Specific questions missed the general rule that answers them: "Who has to approve a high-risk AI system?" ranked UNSW's approval process below 50th, and Copilot data questions found only Copilot pages. Both now find the rule. A cap of 3 lost answers that need several passages from one page; weighting the rewrite higher lost DeepSeek | Synonym maps (keyword side only); weight the rewrite higher; a semantic reranker (can't rerank what wasn't retrieved); send more passages without a cap | Proposed |
| CI role trust | Both roles trust `main` only (2 Nov 2026: pull requests removed from the CI role, since the gate runs on main) | A pull request or any other branch can't read the model keys or deploy; on a public repository, a pull request from anyone can't spend on the models | Pull requests and `main` (the earlier setting); any branch (`refs/heads/*`) | Decided |
| Document conversion | PDFs: PyMuPDF4LLM 1.28 in layout mode, OCR off. Web pages: MarkItDown on the page's `<main>` element | Tested on two corpus PDFs (30 Oct 2026): nested headings that match each document's contents, sidebars kept, running footers dropped, tables kept, about 3 to 10 s per PDF, about 230 MB installed. Headings give each chunk its path for citations. Licence is AGPL 3.0 (or commercial); the ingest job is not a network service and its image is not distributed, so nothing extra is owed unless that changes | MarkItDown for PDFs: no headings at all (plain pdfminer text). Docling: MIT and catches as many headings, but every heading comes out at one level, 30 to 290 s per PDF on CPU and about 6 GB installed. Azure AI Document Intelligence: a new paid service and key | Decided |
| Blocked downloads | Five federal sources whose sites refuse automated downloads are read from copies saved by hand in `ingest/docs` (`file:` in `sources.yaml`); answers still cite the publisher's URL | The sites reset connections from our honest `PolicyDesk-ingest` user agent (30 Oct 2026), and we don't pose as a browser. All five are CC BY, so keeping copies with attribution is allowed. The weekly job can't see updates to them, so they're re-downloaded when licences are rechecked | Pose as a browser; ask each publisher to allow our user agent; leave them out (most of the federal policy) | Superseded 31 Oct 2026: the federal sources left the corpus and the saved-copy feature was removed |
